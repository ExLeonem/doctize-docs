Setup

Command line

The generate and init commands.

$ doctize --help
$ doctize generate --help

generate#

Builds the site.

doctize generate [-c <config>] [-m <model>]... [-g <dir>] [-t <dir>] [--theme-name <name>] [-o <dir>]
                 [--github-pages] [--base-url <url>] [--cname <domain>]
                 [--project-name <name>] [--project-version <version>] [--project-tagline <text>]
                 [--fail-on-warnings] [--serve [--port <n>]]
Option Meaning
-c, --config The configuration file. By default ./doctize.yml if it exists.
-m, --model Where the annotation processor left its output: a compiled classes directory such as build/classes/java/main, a model.json file, or a jar. Repeat the option for several modules. By default build/classes/java/main and target/classes, if they contain a model.
-g, --guides The directory with Markdown guides. Overrides guides in the configuration. By default docs, if it exists.
-t, --theme A custom theme directory. Overrides theme.path.
--theme-name A ready-made theme such as ocean. Overrides theme.name.
-o, --output The output directory. Default build/docs.
--github-pages Prepares the output for GitHub Pages: writes .nojekyll, and CNAME if a domain is set. See Publishing to GitHub Pages.
--base-url The address the site will be published at, e.g. https://acme.github.io/cache/. Enables 404.html, sitemap.xml, robots.txt and canonical links.
--cname The custom domain of a GitHub Pages site, e.g. docs.acme.dev.
--project-name, --project-version, --project-tagline Project data for what the configuration does not set: project.name, project.version, project.tagline. Unlike the other options they do not override the file; the Gradle plugin passes the project's own data this way.
--fail-on-warnings Exits with code 1 if generation produced any warning. Use it in CI so that a broken {@link} fails the build.
--serve Serves the result on http://localhost:<port>/ until you press Ctrl+C.
--port The port for --serve. Default 8080.

Options given on the command line win over the configuration file, except the --project-... options. Relative paths in the file are resolved against the directory of the file; relative paths on the command line against the working directory.

Without any options#

In a project with the usual layout, doctize generate needs no options and no configuration file. Relative to the directory of the configuration file, or to the working directory if there is none, it looks for

  • the output of the annotation processor in build/classes/java/main (Gradle) and target/classes (Maven),
  • Markdown guides in docs,
  • the address of the repository in the Git remote origin (or the first remote), used for the repository link and the GitHub Pages address. Only addresses on github.com, gitlab.com, bitbucket.org and codeberg.org are used, and without credentials; set project.repository to link to any other host.

If it finds nothing to document, the message says where it looked.

Warnings#

Problems that do not stop the site from being generated are printed to standard error as doctize: warning: ... and do not change the exit code, unless you pass --fail-on-warnings. Doctize warns about {@link} tags that point to no documented type or member (links to JDK classes are not checked), and about GitHub Pages options that lack an address.

The output directory is safe#

Doctize removes the output of a previous run before it writes a new one, so pages you deleted disappear. It does this only in a directory it created itself, recognised by a .doctize-site marker file. If you point --output at a directory with other files in it, those files are left alone.

Exit codes#

Code Meaning
0 The site was generated.
1 Doctize could not generate the site: a missing model, invalid configuration, invalid front matter ... The message names the file and the problem.
2 Invalid command line usage.

themes#

Lists the themes that theme.name and --theme-name can choose, with one line about each:

$ doctize themes
default   The built-in theme: indigo accents, system fonts.
contrast  High contrast for accessibility: black on white, underlined links, strong focus rings.
forest    Moss green on warm off-white; earthy in the dark.
ocean     Teal and deep blue, cool neutrals and rounder corners.
paper     A serif reading theme with a narrow text column, like a printed book.
terminal  Monospace everywhere, square corners and a green prompt.

init#

Creates a starter setup.

doctize init [<directory>] [--name <project name>] [--github-pages]

It writes a doctize.yml, a home page introduction (docs/index.md) and two example guides (one in "Quick start", one in "Setup") into the directory (default: the current one). It refuses to overwrite an existing doctize.yml.

With --github-pages it also adds a hosting block to doctize.yml and a GitHub Actions workflow, .github/workflows/docs.yml, that publishes the site; see Publishing to GitHub Pages.
